# Polish inside the existing system

Modified guidance-only adaptation of upstream `skill/reference/polish.md`; critique-storage, engine/context, hook/detector and automatic handoff steps are removed. See [provenance](../UPSTREAM.md).

Polish is refinement, never concealed redesign. Read DESIGN.md, approved frames, tokens, shared components and neighboring flows. Preserve content, identity and behavior outside the requested task.

## Diagnose before editing

Classify drift: a missing reusable token, a one-off implementation where an existing component fits, an unresolved conceptual mismatch, or a local presentation defect. Fix at the narrowest authorized level. Report conceptual conflicts rather than using polish to choose a new visual system.

Inspect the real path at representative sizes and states with already authorized tools. A prior review is evidence, not a substitute for looking. If a functional defect requires a behavior change outside this task, report it for separate authorization rather than fixing it under visual cleanup.

## Refine consistently

- Follow neighboring navigation, terminology, disclosure and save/recovery conventions.
- Make the primary task/current state clear; align groups to the existing grid and spacing scale.
- Keep type roles, semantic colors, icons and imagery coherent across supported themes and states.
- Preserve keyboard focus, tab order, names/labels, contrast, usable targets and responsive reflow.
- Check long/missing/localized content, loading, errors and permission-limited states when applicable.
- Reuse existing components and tokens. Do not create a new abstraction, change a shared component's behavior or replace factual copy merely to make the diff look cleaner.

## Verify and stop

Inspect the final diff against the starting state, preserving other work. Run relevant permitted checks and use actual rendered evidence where available. State exactly which sizes, interactions and states were checked; mark the rest unverified. Report changes and any unresolved design/behavior issues. Do not write critique snapshots, close backlogs, run a detector or automatically invoke another command.
